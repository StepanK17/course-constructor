### Краткое техническое задание для Backend-сервиса «Конструктор курсов»

**Цель:** Создать центральный API для платформы, которая автоматически генерирует персонализированные учебные курсы на основе материалов пользователя или интернета с использованием RAG.

**Основной стек:** Go, PostgreSQL (основные данные), Redis (очереди задач и кэш), MinIO/S3 (хранение файлов), JWT для авторизации.

---

### 📁 Основные модули и что они делают:

1.  **Аутентификация (`/api/v1/auth/`)**
    *   Регистрация, вход, выход, обновление токена.
    *   Защита паролей с помощью bcrypt, токены живут 15 минут (`access`) и 7 дней (`refresh`).

2.  **Документы (`/api/v1/documents/`)**
    *   Загрузка файлов (PDF, DOCX, TXT, MD) в MinIO.
    *   У каждого пользователя свой лимит (например, 20 файлов, 100 МБ).
    *   После загрузки файл отправляется в очередь Redis на обработку AI-сервисом (например, для извлечения текста).

3.  **Курсы (`/api/v1/courses/`)**
    *   **Генерация:** Пользователь задает тему, цель, уровень — сервис создает задачу генерации и ставит её в очередь Redis для AI-сервиса.
    *   **Отслеживание статуса:** Можно проверить, на каком этапе (`pending`, `processing`, `completed`) находится создание курса.
    *   **Список и просмотр:** Получение списка своих курсов (с фильтрами и пагинацией) и деталей конкретного курса со структурой уроков.

4.  **Уроки и прогресс (`/api/v1/lessons/`, `/api/v1/progress/`)**
    *   Получение содержимого сгенерированного урока (текст, код, тесты).
    *   Отметка уроков как пройденных и автоматический расчёт общего прогресса по курсу.

---

### 🗃️ Как хранятся данные (PostgreSQL, основные таблицы):

*   `users`: Профили пользователей.
*   `documents`: Информация о загруженных файлах (имя, размер, статус обработки).
*   `courses`: Метаданные курсов (название, описание, уровень, параметры генерации).
*   `lessons`: Содержимое уроков, связанное с курсом.
*   `user_progress`: Отслеживание, какие уроки какой пользователь прошёл.
*   `generation_tasks`: Очередь и статус задач на создание курсов.

### 🔁 Как работает асинхронная генерация (Redis):
1.  Пользователь нажимает «Создать курс» во фронтенде.
2.  **Backend (Go)** создает запись в `generation_tasks` и кладет сообщение в очередь Redis (`generation_queue`).
3.  **Отдельный AI-сервис (Python/другой)** постоянно «слушает» эту очередь, забирает задачу, выполняет (общается с LLM, RAG) и обновляет статус задачи и данные курса в БД.
4.  **Пользователь во фронтенде** видит статус «В процессе», а по готовности — «Курс создан».

### ⚙️ Что нужно для запуска:
1.  **Переменные окружения** для настройки подключений (URL БД, Redis, ключи).
2.  **Docker-образ** для простого развертывания.
3.  **Миграции БД** для создания таблиц.

---

### 🎯 Итог: что получится?
**REST API**, который позволяет:
*   Пользователям зарегистрироваться и войти.
*   Загружать учебные материалы (документы).
*   Запускать создание персонализированного курса по запросу, выбирая тему, сложность и источники.
*   Отслеживать процесс генерации в реальном времени.
*   Изучать сгенерированные пошаговые уроки и следить за своим прогрессом.

**Главная фишка:** Вся тяжелая работа по генерации контента (общение с LLM, поиск в RAG) выполняется асинхронно в фоне, не блокируя пользователя. Backend лишь управляет задачами, статусами и предоставляет готовые данные.






AI Worker: Техническое задание для модуля генерации курсов (Self-Hosted)
1. Назначение модуля
Заменить текущий демо-воркер на полноценный сервис, который принимает задачу из очереди Redis и генерирует один цельный, структурированный текст курса (как ответ LLM в чате). Разбиение на модули/уроки пока не требуется. Весь процесс выполняется внутри инфраструктуры без платных внешних API.

2. Архитектура и технологический стек
Компонент	Технология / Модель	Обоснование выбора
Основной фреймворк	Python, библиотеки 🤗 Transformers, 🤗 Datasets	Стандарт для работы с open-source моделями, готовые пайплайны.
Модель генерации текста	Qwen/Qwen2.5-3B-Instruct или meta-llama/Llama-3.2-3B-Instruct	Баланс качества и размера. Работают на CPU или GPU (6+ ГБ VRAM).
Модель эмбеддингов (RAG)	sentence-transformers/all-MiniLM-L6-v2	Легкая модель для семантического поиска, работает на CPU.
Векторная база данных	Qdrant (планируется к добавлению)	Для семантического поиска по материалам.
Очереди задач	Redis (уже в проекте)	Связь Backend и AI Worker.

3. Детальный алгоритм работы
Воркер, слушая очередь generation_queue, выполняет следующие шаги для каждой задачи:

Извлечение контекста (RAG):
- Если в задаче есть document_ids, извлекает текст из файлов в MinIO, разбивает на чанки, строит эмбеддинги и сохраняет в Qdrant.
- Если выбран источник "интернет", использует SearXNG (планируется) для сбора информации по теме.
- Формирует релевантный контекст для LLM.

Генерация цельного текста курса:
- Загружает модель генерации текста.
- Отправляет промпт с темой, целью обучения и найденным контекстом.
- На выходе получает один цельный текст с заголовками (например: "## Модуль 1", "### Практика"), но в виде единого ответа.
- Сохраняет результат в `courses.content_text`.

Обновление статуса:
- Обновляет `generation_tasks` и статус курса в PostgreSQL.
- UI опрашивает `/api/v1/courses/{id}/content` и отображает статус в реальном времени.

4. Требования к инфраструктуре (дополнение к docker-compose.yml)
yaml
ai-worker:
  build: ./ai-worker  # Папка с Dockerfile для Python-сервиса
  environment:
    - HF_HOME=/cache
    - MODEL_TEXT=Qwen/Qwen2.5-3B-Instruct
    - MODEL_EMBEDDING=sentence-transformers/all-MiniLM-L6-v2
  volumes:
    - model-cache:/cache  # Для кэширования моделей
    - ./ai-worker/app:/app
  depends_on:
    - redis
    - qdrant  # Планируется к добавлению
  deploy:
    resources:
      reservations:
        devices:
          - driver: nvidia
            count: 1
            capabilities: [gpu] # Опционально, для ускорения. Без этого используется CPU.

5. Критерии приемки для AI-модуля
- Воркер слушает Redis и корректно обрабатывает задачи.
- Модель генерации текста и эмбеддингов успешно загружаются в Docker-контейнере.
- На основе тестового документа генерируется осмысленный цельный текст курса.
- Результат сохраняется в `courses.content_text`.
- Весь процесс выполняется без платных внешних API.
- Статус задачи отражается в интерфейсе.

6. Формат промпта и ожидаемый вывод (предложение)
Цель: получить единый текст, похожий на ответ LLM, с заголовками для логических блоков.

Пример промпта:
```
Ты — преподаватель. На основе темы, цели и контекста создай единый структурированный текст курса.
Требования:
- Выводи один цельный текст (без JSON).
- Используй обычные заголовки: #, ##, ###.
- Отмечай разделы "Практика" и "Квиз" как подзаголовки.
- Укажи источники в конце раздела "### Источники".

Тема: {topic}
Цель: {goal}
Контекст: {context}
```

Ожидаемый формат ответа:
```
# {Название курса}

Краткое введение.

## Модуль 1: ...
Теория...

### Практика
- ...

### Квиз
- Вопрос 1...

### Источники
- ...
```
